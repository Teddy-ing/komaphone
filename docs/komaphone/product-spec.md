# Komaphone product baseline

Version 1.4, frozen 2026-11-08, with the owner-approved network acceptance clarification recorded 2026-11-14. This baseline defines the intended product, not implemented functionality. The owner chose Windows desktop first, a small private sync service, and Animation plus Exquisite Corpse before the shared canvas; approved tours, catch-up playback, and remix; and clarified Endless Paper as the canvas-experience reference with multiple named canvases and independently chosen member lists of variable size. Earlier named friend groups were examples, not presets or a four-person product limit. Baseline 1.4 adds GCP hosting, Google sign-in, and K6.5 hosted friend access before K7, targeting USD $20/month or less with approximately $30/month acceptable. Defaults below fill remaining details so agents can work without repeated product questions.

## Purpose

**Later owner replay decision — 2026-11-18:** QOL-014 may use bounded sampled/keyframed replay for new party submissions; reliable gameplay takes priority over uploaded per-stroke fidelity. This supersedes the earlier rejection of thinning for this party submission path only. Preserve exact final editable drawing, canonical pixels/seam, local undo/recovery, truthful sampled timing and compatibility with old games/archives. Shared-world replay is unaffected. Implementation and compatibility still require evidence; see the later clarification in [QOL-014 requirements](adjustments-drawing-exports.md).

**Additional queued requests — 2026-11-18:** [QOL-009 through QOL-014](adjustments-drawing-exports.md) prioritize shared-canvas party-brush/opacity parity, then basename-only exports to a dedicated app-managed folder with format-selected extensions and Show in folder. They also add Workroom navigation, a local collaborator-name toggle, stable world catch-up playback and an evidence-first investigation of oversized party replay submissions. Existing replay fidelity requirements remain; the supplied sampled-timelapse suggestion is not an approved replacement. These are queued target behaviors, not implementation claims.

**Owner-approved queued amendments — 2026-11-18:** [QOL-002 through QOL-008](adjustments-2026-11-18.md) specify per-creature reveal reset, collapsible canvas navigation, bottom-left dimensions/zoom, reuse of PhotoCraft layer options, continuous dot-spray MS Paint Airbrush, and per-player corpse segment height changes during drawing. QOL-007 supersedes fixed/equal-height assumptions when implemented: width and three rounds stay fixed, each submitted segment retains its own height, and assembly sums those heights without scaling art. Existing fixed-height files remain compatible. These are approved target changes, not implemented acceptance evidence; baseline 1.4 release history remains intact. Invite-only admission review is explicitly deferred and retains H2's existing private-access requirement.

Komaphone lets a small group of friends draw, surprise one another, and keep what they make. It combines the approachable play of a drawing party game with useful editor tools, dependable saves, and an uncluttered interface for adults. The long-term shared canvas is a place to build an increasingly detailed world together, including when friends are online at different times.

Success means friends can install it, complete both party modes with a mouse, close and reopen without losing acknowledged saves, enjoy the reveals, and export their work. A later release adds a collaborative world with genuinely nested detail. Photoshop parity is not the product goal.

## Drawing workspace

**E1 Essential tools.** Brush, pencil, eraser, bucket fill, eyedropper, colors/palettes, basic shapes, selection/lasso, move/scale/rotate, simple text, and image import. Visible brush size, opacity, hardness where supported, smoothing, and presets. Include both thin and very broad brushes within tested resource limits. Brush size follows document coordinates and remains predictable while zooming.

That brush-size rule applies to finite party drawings. In the shared canvas, default to a consistent on-screen brush size when beginning a new stroke at the current zoom, with an explicit lock for thickness in canvas coordinates. Capture the chosen scale with the stroke so later navigation does not resize existing marks. This makes drawing tiny new details as convenient as drawing the larger scene.

**E2 Navigation.** Smooth cursor-centered wheel zoom, drag/space pan, fit view, reset zoom, and visible current tool. Useful keyboard shortcuts and discoverable buttons for undo/redo. Standard finite party canvases can be zoomed closely; the multiscale world is a separate capability.

**E3 Layers.** Add, rename, reorder, hide, duplicate, delete, lock, and change opacity. Show a compact layer list. Keep existing editing capabilities available through an Advanced workspace where practical; do not remove functioning subsystems just to simplify the primary screen.

**E4 Scope control.** No new AI generation, professional color/prepress workflows, vector authoring suite, RAW pipeline, plug-in ecosystem, or Photoshop-parity campaign. Simple shapes may reuse vector internals without exposing a complex vector workflow. Existing capabilities remain compatible.

**E5 Game constraints.** The party editor only edits the assigned frame/segment. Reference images, handoff notes, and seam strips are overlays or side panels, never silently baked into artwork. Advanced commands cannot bypass assignment boundaries or export hidden game content.

## Rooms and common game rules

**L1 Lobby.** Create/join privately, show participants and connection state, choose mode, set round options, ready up, and start. Joining needs a real capability/token, not a guessable short room number alone. Names are labels, not identity or authorization.

**L2 Flow.** Lobby -> active round -> submissions accepted -> next round -> reveal -> archived game. A submission is immutable once accepted. Repeated clicks/retries cannot create duplicates. Rejection leaves a recoverable local draft. A saved local draft and an accepted submission are different states.

**L3 Interruptions.** Disconnect preserves the assignment and draft. Reconnect restores the same player and turn. The default policy pauses progression for a missing player; the host can explicitly skip with a labeled placeholder or end and archive an incomplete game. A timed round pauses on disconnect in the initial release. On deadline, freeze each connected editor and submit its last locally durable work; the service allows a bounded transfer grace, then records explicit missing submissions. It never invents a completed drawing.

**L4 Host and membership.** Freeze the roster/order when a game starts. New arrivals wait for the next game. The host is a moderator, not the only copy of game state. On host disconnect, pause; another connected participant may claim moderation through one service-serialized transition. Service restart restores the room at its last committed transition. No hidden in-memory-only rounds.

**L5 Privacy.** Each participant receives only the assignment and reference material permitted for that phase. Never deliver newly unauthorized artwork through payloads, thumbnail caches, exports, automation inspection, or replay before reveal. The party UI must not surface forbidden prior content. A player may retain their own previously authorized drawings and recovery files; the design cannot erase that knowledge, especially when the two-player corpse rotation returns to the head author. Preserve those private drafts without exposing other players' work. This is private play among friends, not an adversarial tournament; the service administrator can access stored content in the initial design.

## Animation

**A1 Parallel chains.** With N players, create N separate animations. At round r (zero-based), chain owner i is edited by player (i + r) modulo N. Everyone draws one frame per round. Default length is two rotations, 2N frames per animation; the host may choose one to four rotations before starting.

**A2 Reference.** Round zero starts blank. Later rounds show only the immediately preceding submitted frame, with a side-by-side view and adjustable onion skin. Start the new frame blank by default; provide an explicit Copy previous frame action for convenient incremental motion. The previous frame remains immutable.

**A3 Handoff instructions.** A short optional note accompanies each submitted frame for the next editor. Notes are metadata outside the image. They are excluded from frame rasterization, GIFs, and drawing replays; show them in reveal only if the viewer explicitly opens notes.

**A4 Reveal.** Show every chain with participant credits and frame order. Play/pause, scrub individual frames, adjust playback speed, and choose looping. Each frame can show its own drawing timelapse; the finished animation also plays as a whole. These are distinct playback modes.

**A5 Export.** Download/save an animated GIF, a PNG frame sequence, and an editable game archive. Default playback is 6 frames per second, adjustable from 1 to 24. Respect GIF timing/color limits, show a preview, and keep source frames lossless in the archive. Export failure never discards the original.

## Exquisite Corpse

**C1 Parts.** Each player starts one creature. Three rounds produce head, torso/arms, and legs/feet on equally wide, vertically stacked bands. Use the same rotation formula as Animation, for exactly three rounds.

**C2 Small groups.** Three players produce creatures with three authors each. With two players, the head author also draws that creature's legs; this is intentional and explained in the lobby. Both configurations must be tested. This keeps the mode usable with one friend.

**C3 Joining strip.** The head/body editor draws to the bottom edge of their segment. The next editor sees only its last 24 px as a locked reference strip above their own blank segment. The reference does not consume or duplicate output pixels. The strip provides alignment at the neck/waist while hiding the rest. No full prior segment is delivered before reveal.

**C4 Reveal/export.** Assemble each creature in the correct order at full resolution, without gaps, duplicated seam rows, or an added reference overlay. Allow part-by-part reveal, full view, per-part drawing replay, PNG export, and an editable archive. Preserve author credits separately from artwork.

## Saving replay and gallery

**R1 Honest durability.** Track Drawing/Unsaved, Saved locally, Sync pending, and Synced independently. A save indicator follows confirmed durable storage, never just an enqueued job. Every completed edit and submitted artifact must survive a process kill after its save acknowledgment. An unfinished stroke may lose only its not-yet-durable portion; do not claim zero loss for unacknowledged input.

**R2 Recovery.** Resume drafts, game position, submissions, and shared-world edits after normal close, process termination, or network loss. Store game IDs and data beyond the upstream temporary recovery lifecycle. Disk-full, corrupt/truncated records, failed exports, and schema upgrades return actionable errors while preserving the last readable version.

**R3 Replay.** Capture drawing history from the first new Komaphone document, even before the reveal player is built. Record timing, resolved brush/settings/assets, erasing, fills, transforms, layer edits, and undo/redo. Timelapse reflects what was drawn and subsequently changed; imported images may appear as one step. Unsupported commands get a persisted checkpoint step rather than silently disappearing from playback. Legacy imports start from a baseline image with no invented earlier history.

**R4 Recovery versus backup.** Local saves protect against app interruption, not disk loss. The service preserves synced artifacts; provide a portable full archive and a documented backup/restore procedure. No automatic pruning of unsynced work. Set explicit quotas, surface space usage, and stop accepting growth gracefully at the limit. Deletions go through recoverable trash before permanent removal.

**G1 Gallery.** Organize local artwork into four sections — **Saved** (explicitly saved solo drawings, editable back in the Workroom and updated in place), **Completed** (finished/incomplete Animation and Exquisite Corpse games with room-history downloads), **Temp** (automatic local recovery drafts of unsaved Workroom work, with `Save to gallery` promotion and reversible `Clear temp`), and **Trash** (recoverable deleted items with restore and two-step permanent delete / `Empty trash` reclaiming local storage). Show thumbnails, readable viewer-local dates, authors, kind, and state; support search, rename, replay, remix, and format-appropriate export. Store originals and metadata, not only thumbnails/GIFs. Local-only drafts stay private; accepted game artifacts are shared with room participants after their permitted reveal. Untouched blank `file.new` canvases and party-round drafts already preserved in a Completed game do not clutter Gallery and auto-prune safely when closed. Shared Canvases (`World`) and Local Continuous Canvases (`Canvases`) remain completely excluded from the Gallery for now (they use their own dedicated canvas lists).

**G2 Remix finished work.** A Remix action copies a revealed creature, animation, or selected frame into a new editable project, or into an owned region of the shared world once that destination exists. Keep full animation frames and timing unless the user explicitly chooses a still frame. The copy gets its own identity and editable ownership; changes never modify the original. Preserve source revision, authors, and a visible attribution link in metadata and archives without burning credits into artwork. The copied result becomes the new replay baseline; retain access to the original history separately without pretending the remixer drew it. Required local-project remix ships with K4; the shared-world destination ships with K6. Unrevealed game content is never a remix source.

## Persistent shared world

The owner-selected experience reference is [Endless Paper](https://www.endlesspaper.app/): continuous spatial drawing and deep zoom. Its [manual](https://www.endlesspaper.app/manual.html) also documents a gallery for creating, switching, and renaming canvases. Komaphone implements its own mouse-first Windows experience and adds private simultaneous/asynchronous collaboration; this is a behavior reference, not a promise of complete feature, rendering, or platform parity. Implement independently without copying proprietary code or assets.

Use **canvas** in the product UI. A `World` is the implementation's persistent canvas object; each contains its own nested drawing regions. Regions inside a canvas are not separate gallery canvases and do not have separate member lists.

**W1 Independent space.** Persistent canvases live outside timed lobbies. Create and name more than one, keep some solo, and invite different friends to each as specified in W9. Open a canvas anytime; edits persist between sessions. Service availability lets Alice upload, leave, and Bob later download without Alice's computer staying on. During service outage, local editing queues changes and visibly waits for sync.

**W2 Lateral expansion and deep detail.** Pan beyond the original region and draw, letting the app create storage regions as needed. Zoom into a hut, then a pipe, then a tiny house, then another scene and continue adding detail at each scale. Increasing the magnification of one bitmap does not satisfy this requirement. Use bounded local coordinate spaces and progressive rendering; evaluate retained strokes, raster regions, or a hybrid in K5 rather than mistaking one rendering strategy for the requirement. Demonstrate usable new strokes and stable existing marks across scales; imported raster assets retain their source-resolution limits. Depth and storage are finite in implementation; expose honest limits instead of promising mathematical infinity.

**W3 Interaction.** Zoom or pan, then draw directly at that location and scale. Create/select internal detail regions automatically; no mandatory Draw detail here action, visible tile border, or separate document-opening step. Support mouse-centered zoom, pan, zoom out/home, and location bookmarks. Include smooth automatic zoom playback toward a chosen detail/bookmark, plus pause and cancel; browsing never edits artwork. K5 proves single-target auto-zoom; K6 extends it into the required guided tours in W7.

**W4 Collaboration.** A canvas's chosen members can draw simultaneously, see named ghost cursors and in-progress stroke previews, reconnect, and receive durable edits. Membership is a dynamic collection with no fixed four-person product cap, enumerated friend slots, or predefined group combinations. Separate total invited membership from the number of concurrent connections. Keep allocations/messages bounded, paginate/chunk membership and sync where needed, and make any operational capacity limit configurable, visible, and justified by measured resources; do not claim infinite hardware capacity. Acceptance includes groups larger than four, and test sizes are not product ceilings. Each person owns editable layers within regions initially; they may see one another's work but cannot erase it accidentally. Personal undo only reverses that author's operations, never the entire shared canvas. Shared destructive editing is deferred. The party-game roster remains two or three players.

**W5 Offline merge.** Reconnecting merges independent operations with stable identities and deterministic ordering. Duplicate/reordered messages converge. Conflicting metadata or references preserve a recoverable variant and explain resolution. Server timestamps alone are not a merge algorithm. Never replace a newer world with an old whole-document upload.

**W6 Performance and archives.** Load/render visible regions and suitable previews, with bounded caches; avoid loading the entire world every frame. Export a selected view/region to PNG and the full world to a portable archive. Full-world flat PNG export is not meaningful for arbitrarily extended/deep content. Validate the scene model before building the full world UI.

**W7 Guided zoom tours.** Save named routes through multiple bookmarked details, reorder stops, and set travel speed and pause duration. Play, pause, scrub, cancel, and replay the route through lateral and deep-zoom transitions without editing the world. Export the rendered journey as an animated GIF and PNG frame sequence, using a frozen world revision so concurrent edits cannot change the export halfway through. Exclude UI, cursors, and review highlights from exported artwork. Offer bounded duration/resolution settings and keep the original world and route intact on failure or cancellation. Tours persist through save/reopen, sync to world members, and travel with world archives. Missing/deleted destinations show an actionable repair or skip option. This is a required K6 feature.

**W8 Since you were away.** On returning to a world, show changes since that viewer's last reviewed revision, highlight affected regions by author, and jump to each location even at deep scales. Replay the interval with play/pause/scrub/speed controls, including erases, undo/redo, deletions, remixes, and edits uploaded after offline work. Default to friends' changes with an option to include your own; author filtering controls highlights and navigation while replay preserves canonical scene history. Keep unseen changes until explicitly reviewed or marked seen; background synchronization does not clear them. Review uses a fixed end revision so new arrivals stay unseen. First visits start with a clearly labeled current-state baseline. Presence/cursor motion is excluded, and reviewing changes never modifies artwork. This is a required K6 feature, including restart/offline recovery of the review position.

**W9 Named canvases and invitations.** A Canvas Gallery lets each person create, name, rename, and switch among independent canvases. New canvases are owner-only by default. Each has a stable ID, owner, editable member list, thumbnail, save/sync state, and its own drawings, history, bookmarks, tours, and catch-up position. The owner can invite or remove individual friends per canvas; accepting an invitation gives access to that canvas's shared content/history, not the owner's other canvases. Other members can leave without deleting the canvas or their already accepted artwork. Owner controls membership, canvas naming, and recoverable whole-canvas deletion; editors retain author-local editing rules. Membership persists when anyone goes offline and does not depend on party-room membership. No single-canvas limit; validate multiple canvases within explicit storage quotas.

Illustrative examples only: you can share one canvas with Bob, another with Joe, another with Joe and Kelly, and another with Bob, Joe, and Kelly. You may add more people, choose other combinations, keep a solo sketchbook, or have multiple canvases with the same group. Any user can own canvases; Bob may create one with Kelly that does not include you. There is no privileged human who must belong to every canvas. These names and combinations must never become fixed UI options, schema slots, or group-size limits. Show each user only the canvases they belong to. Access checks cover listings, names/thumbnails, assets, edits, presence, replay, exports, tours, and catch-up. A guessed canvas ID or shared asset hash never grants access.

Removing a member blocks subsequent server reads/writes/presence and invalidates their canvas invitations or sessions as appropriate. It cannot erase already downloaded artwork. Rejected offline edits remain recoverable locally, with a clear access-removed state; they must not silently rejoin or enter another canvas. Duplicating/restoring a canvas makes an independent owner-only copy, preserving artwork/credits without copying active invitations or granting membership. Moving/remixing selected art between canvases is an explicit copy into a named destination with access checks on both ends; it does not link their member lists or expose unrelated source content.

Required delivery order: K4 local remix; K5 continuous drawing and multiple named local canvases with durable IDs; K6 arbitrary per-canvas member selection, variable-size sharing, tours, catch-up playback, and world remix. K5's local canvas list must not imply that sharing is already implemented.

## Hosted friend access

**H1 Internet play without network setup.** Host the private Rust service on GCP Compute Engine behind trusted HTTPS. A friend installs the Windows app, signs in, accepts a private invitation, and plays from another household without Tailscale, a VPN, router port forwarding, or manual certificate installation. A public network endpoint does not imply public signup, discovery, or artwork. Local drawing and queued edits remain usable during service/network outages. K4 LAN success is not evidence of this requirement.

**H2 Google identity and existing work.** Use Google sign-in through the system browser for hosted access. Link the verified account to a stable Komaphone profile while retaining separate device actors and preserving existing drawings, canvas IDs, credits, permissions, and unsynced work. Linking requires proof of the existing profile/device credentials; matching a name or email is insufficient. Service admission, room permissions, and per-canvas membership remain separate from sign-in. Sign-out/account switching must not upload another account's queue or discard local recovery data. Local drawing does not require a Google account or an available login service.

**H3 Affordable durable hosting.** Target total recurring USD $20/month or less; approximately $30/month is acceptable for measured resource needs. Count VM, address, storage, backups, traffic, logs, and any domain; show the ongoing total before credits and separately report eligible credits/expiry. Prefer one small VM with durable storage, supervised restart, renewable trusted HTTPS, and verified off-VM backups. Measure memory/load/storage before resizing. Budget alerts are notifications, not a hard spending cap. Materially exceeding approximately $30/month needs a concrete owner decision; do not silently grow recurring spend or delete artwork to meet the target. See the [hosting plan](hosting-plan.md).

**H4 External acceptance.** K6 establishes identity/linking and hosting feasibility foundations. K6.5 completes hosted sign-in and actual Windows play across independent public internet connections: both party modes, reconnect/service restart, independent canvas permissions, simultaneous and non-overlapping use, and backup restoration. Under the owner-approved network clarification, home broadband plus a cellular hotspot with phone Wi-Fi disabled qualifies for K6.5 even when both PCs are in one home. Record that exact topology; do not call it different-household onboarding. No VPN/manual-cert workaround, mocked login, or same-LAN test substitutes for this gate. K7 retains fresh friend onboarding from another household, verifies fresh installation/update, and hardens this proven hosted path. Missing project access or real independent-network clients leaves the applicable external gate explicitly pending while independent preparation continues.

## Scope boundaries and revisions

Classic prompt/draw/guess, public sharing, social feeds, competitive scoring, voice chat, mobile, production browser multiplayer, party games beyond the current two/three-player rules, AI art, and simultaneous editing of the same destructive pixel layer are deferred. Variable-size private canvas membership is required; it does not imply public-scale hosting or unlimited resources. Keep this baseline stable; agents may refine mechanisms and tune bounded defaults with recorded evidence, but must not redefine a requested experience as complete by reducing it.
